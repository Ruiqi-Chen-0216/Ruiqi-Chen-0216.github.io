Ruby & Richard Calendar

Privacy Policy

Effective and last updated: September 22, 2026

Ruby & Richard Calendar is a personal desktop application maintained by Ruiqi Chen. This policy covers the application and its information pages under /calendar/ on this website. Contact: ruiqich@umich.edu.

Information the app accesses

  • Google account identity: the email address and account identifier of each account you authorize, used to identify and manage the calendar connection.
  • Calendar information: calendar names and identifiers, access roles, and event information such as titles, start/end times, time zones, all-day dates, locations, descriptions, attendees, recurrence identifiers, and links to the original events.
  • App-created information: Together event details, calendar ownership labels, display preferences, and synchronization state.
  • Connection information: Google access and refresh tokens, and, if you enable device sync, the GitHub repository configuration, access token, device name/identifier, and shared pairing key.

The Google authorization request uses openid, email, and calendar.readonly. The app does not request access to Gmail messages or Google Calendar write permissions.

How information is used

Information is used to show your selected calendars, distinguish accounts, display events in the chosen time zone, combine duplicate invitations, support offline viewing, and synchronize the events you choose to share. Together events are created and edited within the app; they are not written to Google Calendar.

Calendar data is not sold, used for advertising, used to determine creditworthiness, or sent to AI providers to train or run AI models. There is no advertising or analytics integration in the desktop app.

Ruby & Richard Calendar’s use and transfer of information received from Google APIs will adhere to the Google API Services User Data Policy, including the Limited Use requirements.

Where information is stored

The app keeps calendar data in a local database on each participating computer. Calendar cache contents are not separately encrypted by the app; access depends on the computer’s account permissions and disk protection. Google tokens, GitHub tokens, and the pairing key are protected using the operating system’s credential encryption support.

Google credentials stay on the device that authorized the account. They are not included in shared calendar snapshots or published on this website.

Optional sharing through GitHub

If you configure device sync, selected read-only Google calendar snapshots and Together events are encrypted on the device before being stored in a private GitHub repository. Devices with repository access and the same pairing key can decrypt those records and display their own local copies. A receiving device does not need to sign in to the original Google account.

This sharing includes event titles, times, locations, descriptions, attendee information, and related calendar metadata when present. Device names and source update times help recipients understand where the copies came from. Configure sharing only with the account owner’s permission and only for intended participants.

Google processes authentication and Calendar API requests. GitHub stores the encrypted sync files and processes repository/account metadata under its own policies. Network requests use HTTPS. The app has no separate developer-operated calendar backend. People who control a paired device can read its cached calendar data; encryption in transit or in the repository does not hide events from those intended recipients.

Retention, revocation, and deletion

  • Stop Google access: disconnect the account in the app’s calendar settings, and optionally revoke the app in Google Account third-party connections. This does not delete events in Google Calendar.
  • Stop sharing a calendar: disable its source in calendar connection settings and allow a successful device sync to publish the withdrawal. Sidebar visibility checkboxes only hide events on that device.
  • Stop device sync: disconnect GitHub synchronization on the device. This does not automatically erase copies already held by other devices or the remote repository.
  • Remove saved copies: local caches, operating-system backups, and other paired devices may retain previously received data. Contact the maintainer for help coordinating deletion across participating devices and repository storage.

There is no automatic fixed retention period. Data may remain while the app or its backups retain it. Git history may retain older encrypted snapshots after the current file changes or is deleted. Together deletion records may be retained to prevent deleted events from reappearing. Disconnecting or revoking access does not guarantee immediate deletion of these historical copies.

These public information pages

These calendar information pages do not load analytics scripts, set application tracking cookies, display personal calendars, or request Google sign-in. GitHub Pages hosts them and may process visitor IP addresses and request information for service operation and security. See the GitHub Privacy Statement. Other pages on the maintainer’s academic website are outside the scope of this calendar-page disclosure.

Questions and changes

For access, correction, or deletion assistance, email ruiqich@umich.edu. Include only the information needed to identify your request, not passwords, tokens, or pairing keys. Material changes to the app’s data practices will be reflected here and communicated to participating users; additional consent will be sought before new uses that require it.
